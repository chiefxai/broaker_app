# Legal and support content components

- Keep content presentational, caller-owned, and responsive across native and web.
- Read colors and spacing from the shared theme; do not hardcode app palette values.
- Give expandable content accessible button semantics and expanded state.
- Do not imply that a legal request or support ticket reached the backend unless an implemented API supports it.
- Keep component exports in `registry.ts` and forward them from `index.ts`.
